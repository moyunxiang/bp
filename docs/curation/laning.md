# 对线档案提炼规范（清线抢线、对线强弱、射辅组合、前期强弱）

目的：从B站教学视频的字幕里，找出解说**明确说了**的对线判断：某个英雄清线抢线快不快、对线强不强、在发育路双人对线里强不强、前期强不强，以及具体对上谁占优、谁吃亏。每一条都必须能在字幕里找到出处。原始字幕只留在本地，不进仓库。

为什么只能这样做：官方职业赛接口只有终局数据，没有前几分钟的经济；官方技能原文推不出对线胜负。所以这类判断只能来自解说，网站上会标明“这是解说的说法”，并给出视频链接和时间点。

## 输入

`data/raw/commentary/laning/inputs/batch-N.md`。开头是规范英雄名列表，之后有两种小节：

- `## 英雄：某某`：下面几个视频都是在讲这个英雄。字幕只保留了提到对线、抢线、前期等内容的片段，`……`表示中间有省略。解说说的“我们”“你”“这个英雄”通常指这个英雄。
- `## 专题视频 BVxxxx`：整段字幕。这类视频会连着讲很多英雄，每条说法要写清楚说的是谁。

字幕每行是“分:秒 内容”，是自动识别的，有错字和同音字（英雄名尤其常见，如“镜”被识别成“竟”，“马超”被识别成“马操”）。

## 输出

写一个文件 `data/raw/commentary/laning/claims-N.json`（N与输入批次相同），是一个数组：

```json
[
  {
    "hero": "嬴政",
    "aspect": "clear",
    "level": "strong",
    "lane": "中路",
    "claim": "一级学1技能，剑阵能同时打到整波兵，清线比多数法师快",
    "ref": { "bvid": "BV1xxxxxxxxx", "t": 95, "quote": "一级清线非常快" }
  },
  {
    "hero": "后羿",
    "aspect": "lane",
    "level": "weak",
    "vs": "马可波罗",
    "lane": "发育路",
    "claim": "前期没有位移，被马可波罗贴脸换血会吃亏",
    "ref": { "bvid": "BV1yyyyyyyyy", "t": 212, "quote": "前期打马可是打不过的" }
  },
  {
    "hero": "公孙离",
    "aspect": "duo",
    "level": "strong",
    "with": "大乔",
    "lane": "发育路",
    "claim": "大乔的加速和回城让公孙离可以频繁换血后回补",
    "ref": { "bvid": "BV1zzzzzzzzz", "t": 40, "quote": "公孙离加大乔线上非常强势" }
  }
]
```

### 字段

- `hero`：这条说法说的是谁。用规范英雄名。
- `aspect`：
  - `clear`：清线、抢线的速度（清第一波兵快不快、能不能抢到线权、清线后能不能先走）。
  - `lane`：对线强度（线上换血、压制、单杀、抗压的能力）。对抗路、中路、发育路单人层面的强弱都用这个。
  - `duo`：发育路的双人对线。**只用于射手和辅助**：射手有辅助跟着时强不强，辅助跟射手时线上强不强（能不能帮射手压制对面、保住射手）。
  - `early`：前期的整体强度（大约4级前或前4分钟），解说没有具体说对线、只是泛泛地说“前期强/前期弱/需要发育”时用这个。
- `level`：`strong`（快/强/占优）、`weak`（慢/弱/吃亏）、`even`（一般、五五开）。
- `vs`（可选）：这条说法只针对某个对手。`hero` 对上 `vs` 时是 `level`。例如“对线吕布很难打”→ `level: "weak"`, `vs: "吕布"`。
- `with`（可选，只能用在 `duo` 和 `clear`）：这条说法只在和某个队友搭档时成立。
- `lane`（可选）：解说说的是这个英雄走哪一路。只能是 `对抗路`、`中路`、`发育路`、`游走`、`打野`。字幕里看不出来就不写。
- `claim`：用自己的话概括，不超过60个字，**必须包含原因或条件**（为什么强/弱、在几级前、什么情况下）。解说没讲原因时，写清楚成立的阶段或条件。不要照抄字幕。
- `ref`：出处。`t` 是 `quote` 开头所在那一行的行首时间换算成的秒数（`06:18` → 378）；`quote` 是这一行附近字幕里**逐字出现**的一小段（6–24个字，有错字也照抄，不要修正）。脚本会逐字核对 `quote` 是否出现在该视频 `t` 前后60秒的字幕里，对不上的会被丢弃。

同一个视频对同一个英雄的同一方面，只写最清楚的一条。

## 取舍标准

只写解说**明确说了**的判断。不要补充你自己知道但视频没讲的东西，不要推理，不要根据技能描述自己下结论。

要提炼：

- “这个英雄清线很快/很慢”“抢线抢不过别人”“一级就能抢到线权”“清完线可以先去支援”。
- “对线很强/很弱”“前期能压着对面打”“四级前不要和人打”“线上只能抗压”。
- “对线某某好打/难打/打不过/五五开”，并且看得出方向。
- “某射手配某辅助线上很强”“这个辅助跟射手没法帮忙压制”。
- 专题视频里按强弱给英雄分档的内容：每个被明确评价的英雄写一条。

不要提炼：

- 只是教怎么对线、怎么清线的操作（“先用1技能清兵”“卡在兵线中间”），没有说强弱或快慢。
- 版本强度和排名：“T0”“版本答案”“必ban”“胜率多少”。
- 团战、后期、打野节奏方面的强弱（“后期无敌”“团战很强”）。只有同时说了前期或对线，才写前期或对线的那一半。
- 只适用于视频里某一局的情况（“这把对面打野一直来，所以打不过”）。
- 带明显前提的假设（“如果你出了某件装备之后”这类是可以写的，把前提写进 `claim`；但“如果对面不会玩”这类不要）。
- 字幕识别不清、看不出说的是谁、看不出方向的内容。
- 讲的是别的游戏或别的模式。

讲某个英雄的视频容易夸这个英雄。措辞要照实：解说说“前期一般”“还行”就是 `even`，不要写成 `strong`。

宁缺毋滥。一个英雄没有任何明确说法就不写。

## 执行步骤（给做提炼的子任务）

1. 读取 `data/raw/commentary/laning/inputs/batch-N.md`。文件较长，分段读完，不要只读开头。
2. 按本规范写出 `data/raw/commentary/laning/claims-N.json`（UTF-8，合法JSON数组）。
3. 自查：`npx tsx scripts/commentary/laning.ts --check=N`（只核对，不写任何文件）。输出里有“出处对不上”“英雄名无法识别”“格式错误”时，回到字幕里核对并修正：`quote` 改成字幕里逐字存在的片段，`t` 改成正确秒数；确实找不到出处的条目删除。再自查，直到输出“没有问题”。

注意：

- 宁可少写，也不要凭印象写 `quote`。
- 不要修改其他任何文件，不要运行 `laning.ts` 的其他参数，不要动 git。
- 最后用两三句话汇报：一共写了多少条，各 `aspect` 多少条，哪些英雄或视频没有可提炼的内容。

## 复核（给做复核的子任务）

提炼时容易出的错：把“怎么对线”写成“对线强”；把方向写反；把只在某一局、某个条件下的说法写成一般结论；把讲团战或后期的话写成对线；讲A英雄的视频里顺口提到的B英雄被张冠李戴。所以每条说法都要由另一个模型独立复核一次。

输入是 `data/raw/commentary/laning/review/batch-N.md`。每一条有：键（原样照抄）、要判断的说法（一句话，如“嬴政 清线、抢线快”或“后羿 对线 马可波罗 时吃亏”）、提炼出的理由、出处前后约两分钟的字幕。

逐条判断，只有两种结论：

- `keep`：字幕里解说**明确表达了这个意思**，说的是这个英雄，方向一致，而且讲的是对线、清线抢线或前期（和说法的类别对得上）。不必出现一模一样的词，但意思要清楚。
- `drop`：以下任一情况——
  - 解说只是在讲操作方法，没有说强弱或快慢；
  - 方向和解说的意思相反，或者从字幕判断不出方向；
  - 说的不是这个英雄，或者对手、搭档对不上；
  - 讲的是团战、后期、某一局的具体情况、版本排名；
  - 说法的类别不对（例如解说说的是“前期弱”，却被写成“清线慢”）；
  - 提炼出的理由和字幕说的原因明显对不上。

拿不准就 `drop`。不要根据你自己对游戏的了解判断说法对不对，只判断**解说有没有这么说**。

输出 `data/raw/commentary/laning/review/verdict-N.json`（N与输入批次相同），是一个数组，每条输入对应一项：

```json
[
  { "key": "嬴政|clear|||BV1xxxxxxxxx|95", "verdict": "keep", "reason": "解说明确说嬴政一级清线很快" },
  { "key": "后羿|lane|马可波罗||BV1yyyyyyyyy|212", "verdict": "drop", "reason": "解说讲的是那一局被打野抓了，不是一般情况" }
]
```

`reason` 用一句话说明依据，不超过60个字，不要照抄字幕原文。不要修改其他任何文件，不要动 git。最后汇报这一批共多少条、保留多少、剔除多少。

## 之后

```bash
npx tsx scripts/commentary/laning.ts --review-prepare   # 生成复核输入
# 子任务按“复核”一节写 verdict-N.json
npx tsx scripts/commentary/laning.ts --review-apply
npx tsx scripts/commentary/laning.ts --build            # 写入 data/curated/laning.json
npm run build:data && npm run validate && npm test
```

没有复核结论的说法不进入网站。网站上同一个英雄同一方面的结论按**不同UP主**的说法汇总：只有一种说法就用它；两种说法都有时，多的一方至少多出两位UP主才算数，否则显示“说法不一”，不下结论。
