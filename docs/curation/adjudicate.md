# 分歧标签裁定规范

撰写方和盲审方各自独立给英雄打了机制标签。只有一方标注的标签记为“分歧”，目前不参与计分。你的任务是对每条分歧做最终裁定。

## 输入

`data/curated/_work/disputed.json`：
- `tagDefs`：涉及标签的判定标准。
- `heroes[]`：每个英雄的相关技能原文（`skills`）和分歧条目（`disputed`：`tag`、`slot`、`quote`，`quote` 是提出该标签的一方给出的原文依据）。

## 裁定标准

**唯一依据是给出的技能原文和 `tagDefs` 里的定义**，不要使用记忆中的游戏知识。

- `accept`：原文明确满足该标签的定义。
- `reject`：原文不满足定义，或需要靠推测、靠游戏经验才能成立。拿不准时一律 `reject`。

几条容易出错的口径：
- `aoe_damage`：原文必须能看出一次可以伤害多个敌人（“范围内”“路径上”“周围”“所有敌人”“附近敌人”“前方敌人”等）。只写“命中的敌人/目标”而没有任何范围或多目标表述的，`reject`。
- `cc_hard_aoe`：必须是范围、区域或路径型技能且硬控对其中敌人生效；只能控单个指定目标的 `reject`。
- `reset`：刷新冷却、返还冷却、存储多次使用、同一技能多段释放才算；仅“减少冷却时间”`reject`。
- `dash`：原文必须写明英雄自身发生位移（冲锋、突进、跳跃、闪烁、翻滚、跃向、传送到近处、后撤等）；只写加移速、腾空、消失的 `reject`。
- `execute`：对低生命目标增伤或按已损生命增伤才算；只对非英雄单位生效的 `reject`。

## 输出

对输入里的每个英雄写一个文件 `data/curated/adjudication/{id}.json`：

```json
{ "id": 105, "decisions": [ { "tag": "displace_enemy", "slot": "2技能", "verdict": "reject", "reason": "原文写明只拉非英雄单位" } ] }
```

`decisions` 要覆盖该英雄的每一条分歧，`reason` 用一句话引用原文说明理由。只写 `data/curated/adjudication/` 下的文件，不修改其他文件，不运行 git 命令。

完成后报告：accept 多少条、reject 多少条。
