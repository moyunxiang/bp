# 英雄教学提炼规范（连招、细节、克制关系）

目的：从B站教学视频的字幕里，提炼某个英雄的**连招、操作细节、克制与被克制关系**。每一条都必须能在字幕里找到出处。原始字幕只留在本地，不进仓库。

## 输入

- `data/raw/commentary/hero-videos.json`：键是英雄ID，值是该英雄已取到字幕的视频列表（`bvid`、标题、UP主、时长 `seconds`）。
- `data/raw/commentary/subtitles/{bvid}.txt`：前两行是标题、UP主、发布日期、链接；之后每行是“分:秒 字幕内容”。字幕是自动识别的，有错字和同音字（英雄名、技能名尤其常见，例如“镜”被识别成“竟”“劲”）。
- `data/derived/official/heroes.json`：`heroes[]` 里每个英雄的 `id`、`name`、`skills[]`（`slot` 为“被动”“1技能”…“4技能”，`name` 为技能名，`desc` 为官方原文）。

## 输出

对每个英雄写一个文件 `data/raw/commentary/distilled/{英雄ID}.json`：

```json
{
  "id": 531,
  "name": "镜",
  "combos": [
    {
      "steps": ["1", "A", "1", "A", "2"],
      "name": "基础刷新连招",
      "level": "基础",
      "note": "本体和镜像各打出一种印记后触发刷新，所以两次1技能中间要接普攻",
      "refs": [{ "bvid": "BV1H6sEzNEzS", "t": 378, "quote": "可以说人人都会1A1A二" }]
    }
  ],
  "tips": [
    {
      "title": "2技能接换位瞬移",
      "text": "2技能出手后立刻用3技能换位，可以把伤害打在镜像的位置",
      "refs": [{ "bvid": "BV1K6S4ByE53", "t": 512, "quote": "二技能接换位" }]
    }
  ],
  "matchups": [
    { "type": "countered", "hero": "东皇太一", "claim": "东皇的大招压制期间无法换位脱身", "refs": [{ "bvid": "…", "t": 95, "quote": "…" }] }
  ]
}
```

### steps：连招步骤

- **数字一律按官方技能顺序**：`"1"`=1技能，`"2"`=2技能，`"3"`=3技能，`"4"`=4技能（以 `heroes.json` 里该英雄 `skills[].slot` 为准）。
- 解说的叫法可能和官方顺序不同：很多人把大招叫“三技能”或“大招”，有的英雄玩家还会在设置里对调技能位置。**必须根据解说提到的技能名或效果，对应到官方的技能，再写官方顺序的数字。** 例如镜的官方3技能是【移形】（换位），4技能是【见影】（大招）；解说说“大招”就写 `"4"`，说“换位”就写 `"3"`。
- 判断不出解说说的是哪个技能，这条连招就不要写。
- **切换形态后的技能不要写裸数字**。有的英雄放出技能后按键会变成另一套技能（元歌的傀儡、花木兰的轻剑/重剑、李信的形态等），这些技能不在官方技能表的1–4技能里。写成“形态名+按键位置”的文字步骤，例如 `"傀儡3"`、`"重剑1"`、`"光信2"`。只有确实是官方技能表里那个技能时才写数字。
- 其他步骤：`"A"`=普攻；`"闪"`=闪现；其余用不超过6个字的中文，如 `"惩击"`、`"净化"`、`"强化普攻"`、`"切重剑"`、`"二段1"`。
- 一条连招2–12步。

### 其他字段

- `name`：连招叫法，优先用解说的叫法，不超过12个字。
- `level`：`"基础"` 或 `"进阶"`。
- `note`：这套连招的用途、原理或要点，用自己的话写，不超过60个字。解说没讲就写空字符串。不要带“最强”“无敌”这类强度形容。
- 只有两步的取消后摇手法（如“1技能接普攻取消后摇”）写进 `tips`，不算连招。
- 解说用简称（如“1A1A二”“二一起手”）时，只有每一步是什么都清楚才写成 `steps`。
- `tips[].title` 不超过14个字；`tips[].text` 用自己的话概括，不超过80个字，要具体（什么情况下、怎么做、有什么效果）。
- `matchups[].type`：`"counter"`=这个英雄克制 `hero`；`"countered"`=这个英雄被 `hero` 克制；`"synergy"`=和 `hero` 配合好。`hero` 用规范英雄名（`heroes.json` 的 `name`）。`claim` 不超过60个字，**必须包含原因或条件**。
- `refs`：每条至少一个出处。`t` 是 `quote` 开头所在那一行的行首时间换算成的秒数（`06:18` → 378）；`quote` 是**这一行附近字幕里逐字出现的一小段**（6–24个字，包含错字也照抄，不要修正、不要跨行拼接）。脚本会逐字核对 `quote` 是否出现在该视频 `t` 前后60秒的字幕里，对不上的条目会被丢弃。
- 同一条内容在多个视频里都讲到，就把多个视频的出处都列进 `refs`（这会让它被标记为“多个来源印证”）。

## 取舍标准

只写**解说明确讲了**的内容。不要补充你自己知道但视频没讲的东西，不要推理。

要提炼：

- 连招：基础连招、进阶连招、不同场合（对线换血、切后排、逃生、过墙）的连招。
- 细节：技能的隐藏机制与用法（穿墙点位、取消后摇、卡刷新、技能释放顺序的讲究、被动怎么利用）、对线和团战的进场思路。
- 克制关系：解说明确说“怕谁”“克制谁”“遇到谁要怎么打”，并且给了原因（哪怕只有一句）。单纯的“建议禁用某英雄”不算，除非同时说明了它为什么克制这个英雄。

不要提炼：

- 出装、铭文的具体搭配（官方页面已有推荐）。
- 强度判断和排名：“T0”“版本答案”“无敌”“必ban”“胜率多少”。
- 泛泛的意识类建议：“多看小地图”“注意支援”。
- 只适用于视频里某一局的结论。
- 字幕识别不清、无法确定含义的内容。
- 视频与该英雄无关（字幕讲的是别的游戏或别的英雄）：该视频整体跳过。

数量：连招最多8条，细节最多10条，克制关系最多8条。宁缺毋滥，没有就给空数组。

## 之后

写完后可以先用 `npx tsx scripts/commentary/build-guides.ts --check=英雄ID,英雄ID` 自查（不写任何文件）。

全部完成后运行 `npx tsx scripts/commentary/build-guides.ts`：逐字核对出处，丢弃对不上的条目，把通过的条目（不含字幕原文）写入 `data/curated/guides/`，并汇总进数据包。

## 执行步骤（给做提炼的子任务）

拿到一组英雄ID后，逐个处理，一个做完再做下一个：

1. 读取 `data/raw/commentary/inputs/{英雄ID}.md`。里面有该英雄的官方技能表、规范英雄名列表、若干个视频的字幕（每个视频一节，标题行里有 bvid 和时长）。文件较长时分段读完，不要只读开头。
2. 按本规范写出 `data/raw/commentary/distilled/{英雄ID}.json`（UTF-8，合法JSON）。
3. 全部写完后自查：`npx tsx scripts/commentary/build-guides.ts --check=英雄ID,英雄ID,英雄ID`（只核对，不写任何文件）。输出里有“出处对不上”“没有某技能”“英雄名无法识别”“格式错误”时，回到字幕里核对并修正：`quote` 改成字幕里逐字存在的片段，`t` 改成正确秒数；确实找不到出处的条目删除。再自查，直到输出“没有问题”。

注意：

- 宁可少写，也不要凭印象写 `quote`。
- 不要修改其他任何文件，不要运行不带 `--check` 的 `build-guides.ts`，不要动 git。
- 最后用两三句话汇报：每个英雄各写了多少条连招/细节/克制关系，哪些视频被跳过及原因。

## 克制说法复核（给做复核的子任务）

提炼时容易出两类错：把“遇到某英雄怎么打、怎么应对”写成“克制某英雄”；把克制的方向写反。所以每条克制/配合说法都要由另一个模型独立复核一次。

输入是 `data/raw/commentary/review/batch-N.md`。每一条有：键（`英雄ID|type|对方英雄名`）、要判断的说法（一句话，如“镜 克制 东皇太一”）、提炼出的理由、出处前后约三分钟的字幕（自动识别，有错字和同音字）。注意标明了这个视频是在讲哪个英雄：解说说的“我们”“你”通常指这个英雄的玩家。

逐条判断，只有两种结论：

- `keep`：字幕里解说**明确表达了这个方向的克制（或配合）**，并且说了原因。说法不必出现“克制”两个字，但意思要清楚，例如“这个英雄很怕某某，因为……”“打某某很好打，他的某技能对你没用”“拿它来针对某某”。
- `drop`：以下任一情况——
  - 解说只是在讲遇到对方时怎么打、怎么出装、怎么躲技能，没有说谁克制谁；
  - 方向和解说的意思相反，或者从字幕判断不出方向；
  - 只说了“可以禁用/建议禁用”而没有说它为什么克制；
  - 讲的是某一局的具体情况、某个版本的强度，或者字幕片段里根本找不到这层意思；
  - 提炼出的理由和字幕说的原因对不上。

拿不准就 `drop`。不要根据你自己对游戏的了解判断说法对不对，只判断**解说有没有这么说**。

输出 `data/raw/commentary/review/verdict-N.json`（N与输入批次相同），是一个数组，每条输入对应一项，键原样照抄：

```json
[
  { "key": "531|counter|东皇太一", "verdict": "drop", "reason": "解说讲的是被东皇大招压制时怎么处理，没有说镜克制东皇" },
  { "key": "135|countered|东皇太一", "verdict": "keep", "reason": "解说明确说项羽怕东皇，大招压制期间无法推人" }
]
```

`reason` 用一句话说明依据，不超过60个字，不要照抄字幕原文。不要修改其他任何文件，不要动 git。最后汇报这一批共多少条、保留多少、剔除多少。

全部批次完成后运行 `npx tsx scripts/commentary/review-matchups.ts --apply`，再运行 `build-guides.ts`。
