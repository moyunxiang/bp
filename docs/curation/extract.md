# 英雄机制档案提取规范（撰写方）

你要为一批王者荣耀英雄撰写“机制档案”。**唯一的依据是输入文件里的官方技能原文**。不要使用你自己记忆中的游戏知识：技能可能已重做，记忆中的内容可能过时或有误。原文没写的东西一律不写。

## 输入

批次文件（JSON）：`heroes[]`，每个英雄有 `id`、`name`、`heroType`（官方职业）、`skills[]`（`slot` 为“被动/1技能/2技能/3技能/4技能”，`name`、`cooldown`、`cost`、`desc` 原文）。

标签词表：`data/curated/tags.json`。每个标签的 `def` 是判定标准，严格按它判断。

## 输出

对批次里的**每个英雄**写一个文件 `data/curated/heroes/{id}.json`（用 Write 工具，UTF-8，合法 JSON），结构如下：

```json
{
  "id": 105,
  "name": "廉颇",
  "tags": [
    { "tag": "cc_immune", "slot": "被动", "quote": "廉颇释放技能时处于霸体状态" },
    { "tag": "dash", "slot": "1技能", "quote": "廉颇向前冲锋" }
  ],
  "summary": "一句话说明这个英雄靠什么技能做什么事（不超过40字）",
  "strengths": [ { "text": "……", "refs": ["1技能", "3技能"] } ],
  "weaknesses": [ { "text": "……", "refs": [] } ],
  "combos": [ { "order": ["2技能", "1技能"], "why": "……", "quote": "技能范围内有敌人时会刷新【爆裂冲撞】的冷却" } ],
  "interactions": [ { "text": "……", "refs": ["2技能"], "quote": "技能释放期间可以使用其他技能" } ]
}
```

### tags（最重要）

- 逐个技能对照词表，原文明确写出某效果才标注。**同一标签在不同技能上出现要分别记录**（例如两个技能都有位移，就写两条 `dash`）。同一技能同一标签只记一条。
- `quote` 必须是该技能 `desc` 里**逐字连续**的一段原文，6–40 个字，足以证明这个标签。不要改字、不要省略号、不要拼接两处、不要包含换行。脚本会逐字校验，对不上的标签会被丢弃。
- `slot` 填该原文所在技能的 `slot`。
- 拿不准是否符合定义时不要标。宁缺毋滥。
- `cc_hard_aoe`、`suppress` 必须与 `cc_hard` 同时出现在同一技能上。

### summary / strengths / weaknesses / combos / interactions

- 全部只能写**能从技能原文直接推出**的内容，`refs` 列出依据的技能 `slot`。
- `strengths`：3–5 条。写机制层面的长处，例如“1技能和3技能都有位移，进退手段多”。
- `weaknesses`：2–4 条。只允许两类：①原文体现的限制（如技能有前置条件、冷却很长并给出原文数值）；②“没有某类机制”，例如“没有位移技能”“没有硬控”“没有回复和护盾”，此时 `refs` 为空数组。写“没有某机制”前先确认所有技能原文里确实没有。
- `combos`：0–3 条。**只写原文明确存在联动的技能顺序**（A 命中后强化 B、A 刷新 B、A 标记后 B 触发额外效果等），`quote` 给出写明这一联动的原文（规则同上），`why` 用一句话解释。没有明确联动就给空数组，不要凭经验编连招。
- `interactions`：0–4 条。原文中值得注意的机制细节（特殊条件、例外、与普攻/装备/地形的关系），每条附 `quote`。

### 禁止写的内容

- 强度评价与排名：“版本强势”“T0”“很强”“伤害爆炸”。
- 没有原文数字支撑的伤害、射程、手长短比较。
- 原文没写的隐藏机制：前摇后摇、取消后摇、碰撞体积、技能判定细节。
- 对线胜负断言、出装铭文建议、任何其他英雄的名字（不要写“克制某某”）。
- “职业选手”“高端局”之类无法从原文验证的说法。

## 完成后

用一段话报告：处理了哪些英雄ID、每个英雄的标签条数、有没有哪个英雄的原文让你难以判断（说明是哪句）。不要在报告里重复档案内容。
