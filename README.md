# 王者BP助手

《王者荣耀》英雄克制关系与BP辅助网站。手机打游戏，电脑开着网站：录入双方的禁用和选人，立刻得到带理由的Ban/Pick推荐；同时提供英雄机制百科、克制与配合图谱、战术阵容库。

在线地址：<https://moyunxiang.com/bp/>（`https://moyunxiang.github.io/bp/` 会跳转到这里）

网站是纯静态的，所有推荐都在浏览器里计算，不需要登录，也不依赖任何后台服务。

## 功能

| 页面 | 内容 |
|---|---|
| BP助手 | 排位赛、巅峰赛、自由模拟三种规则；全程可只用键盘录入；自动推测分路，可手动指定；Pick/Ban推荐带推荐分、可信程度和理由，排序由职业赛BP训练的选人模型给出；候选对比；我的英雄池与理论最优切换；研究模式可展开每一项得分的原文依据和双方关系图；“打法”标签给出这一局怎么打：我方打法、对面的突破口、要防的点、出装针对、分路对位（双方选满后自动切到这里） |
| 英雄百科 | 官方技能原文、四维、连招与操作细节（提炼自B站教学视频，逐条带视频出处）、机制标签（带原文引用）、长处与短处、技能联动、克制/被克/配合关系及依据、官方推荐出装、近期版本改动 |
| 分路梯度 | 各分路的英雄梯度，可切换来源：王者营地英雄榜（巅峰赛1350+、顶端排位、所有段位，每个位置热度前10，带胜率、登场率、禁用率）和职业赛（按第一局禁选次数算出场率）；网站每天自动刷新一次营地数据 |
| 关系图谱 | 单英雄的克制/被克制/配合图，可点击继续探索；双方阵容对阵图，可按对线、团战、前期、后期筛选 |
| 阵容库 | 战术体系定义；职业赛中自动发现的阵容与三人组合（只有出现次数）；阵容分析（分路、构成、体系、局内打法、协同、被克点、替代英雄）；每个体系的前期、中期、团战打法和应对办法；阵容对比里可以站在任一方看对阵打法；自定义、收藏、对比 |
| 我的 | 英雄池与熟练度、默认偏好、收藏、导入导出 |
| 数据说明 | 数据来源、更新时间、各类证据的数量、核实情况、规则表、回测结果、已知限制 |

## 这个网站怎么保证不编造

- **关系只来自有据可查的证据**，分四级：官方页面的关系说明 > 由双方技能原文按规则推导的“机制倾向” > 职业赛同队共现 > 解说条目。每条关系都能在界面上展开看到来源。
- **机制标签必须带原文引用**。模型只负责从官方技能原文里提取“某技能有某机制”，并给出逐字的原文片段；脚本逐字校验；另一个模型独立再标一遍；两边一致才算已核实，不一致的由第三方按原文裁定。当前140个英雄的标签一致率为90.0%，已核实标签1429条。
- **克制和配合不由模型直接下结论**，而是由一张人工审定的规则表（`data/curated/rules.json`）根据标签计算。规则给出的是倾向，并写明成立条件。
- **局内打法是通用战术说明，并且有触发条件**。打法表（`data/curated/playbook.json`）里每一条都写明由双方阵容的哪些官方职业、已核实技能标签触发，界面上可以展开看到触发它的英雄和技能原文；点名的装备取自官方装备说明里带对应关键词的装备。它不是数据结论，界面上也这样标注。集火目标和分路对位由关系库的证据计分算出。
- **没有依据就显示“暂无结论”**。约七成的英雄对之间没有任何结论，推荐时不会假设它们存在克制或配合。
- **路人局数据只用王者营地公开页面给出的部分**：每个位置热度最高的10个英雄的档位、胜率、登场率、禁用率，原样展示并注明日期，只用于“分路梯度”页和英雄页，不参与推荐计分。完整榜单和对位胜率需要登录营地App，没有使用。职业赛数据只展示次数和样本量，不计算胜率。
- **推荐分不是胜率**，是可解释的分项按系数加总。系数由一个条件logit模型从职业赛BP中学出（预测职业队每一手选了谁），在没参与训练的2026年对局上检验过才采用；模型、系数和回测结果都在数据说明页公开。
- **阵容底线不靠模型学**。近一年的职业队阵容里99%以上至少有1个硬控、1个坦克或战士、法术和物理两种伤害，但把各位置的常用英雄随机拼起来也是如此——职业赛里基本不出现缺口，模型学不出“缺什么补什么”。路人局会出现缺口，所以这一项按固定分值执行：从第三手起提示“我方还缺什么”，越接近选完，能补缺口的英雄加分越多；最后一手补不上硬性底线的扣分。各条底线在职业阵容里的满足比例见数据说明页。
- **连招和细节必须有视频出处**。每一条都记录了视频和时间点，脚本逐字核对过它在字幕里确实出现；原始字幕不进仓库。
- 官方技能原文变化后，对应英雄的档案会自动标为“待复核”并停止参与计分。

## 本地运行

需要 Node.js 22 及以上。

```bash
npm install
npm run dev        # 开发模式
npm run build      # 类型检查 + 构建到 dist/
npm test           # 引擎单元测试
npm run e2e        # 构建后跑端到端冒烟测试（使用本机 Chrome）
```

## 更新数据

电脑开机时运行即可，网站本身不依赖它：

```bash
npm run update-data                 # 官方资料、公告、职业赛增量、重新校验、生成数据包
npm run update-data -- --backtest   # 另外重跑回测并重新训练选人模型（约12分钟）
npm run update-data -- --commentary # 另外读取B站教学视频字幕（需要先取得登录Cookie，见下）
git add -A && git commit -m "Update data" && git push   # 推送后自动重新发布
```

王者营地英雄榜另外由 GitHub Actions 每天北京时间06:30自动刷新一次并重新发布（只请求营地的公开分享页接口18次；失败就沿用仓库里的数据）。这样电脑不开机，分路梯度页里的路人局数据也是当天的。其他数据仍然只在本地运行 `update-data` 时更新。

网站右上角显示数据更新时间；超过14天会提示可能过期，超过30天会给出醒目提示。

各步骤也可以单独运行：

| 命令 | 作用 |
|---|---|
| `npm run fetch:official` 然后 `npx tsx scripts/parse-official.ts` | 抓取并解析官方英雄资料 |
| `npm run fetch:news` | 抓取正式服公告，提取英雄改动 |
| `npx tsx scripts/fetch-camp.ts` | 读取王者营地英雄榜（公开分享页接口，不需要登录），写入 `data/derived/camp.json` |
| `npm run fetch:kpl -- --since=2025` 然后 `npx tsx scripts/build-kpl.ts` | 抓取职业赛逐局BP（可断点续跑）并聚合 |
| `npx tsx scripts/build-profiles.ts` | 校验机制档案的原文引用并合并 |
| `npm run build:data` | 生成 `public/data/bundle.json` |
| `npm run validate` | 校验数据包（引用完整性、原文引用、存疑内容不计分） |
| `npm run backtest` | 用职业赛历史对局回测推荐排序，并训练选人模型（写入 `data/derived/model.json`） |
| `npx tsx scripts/build-floors.ts` | 统计近一年职业队阵容对各条“阵容底线”的满足比例和随机对照，写入 `data/derived/kpl/floors.json`（展示依据用） |
| `npx tsx scripts/outcome-test.ts` | 胜负检验：阵容上的各项差值与职业赛胜负有没有关系（控制战队强弱后），结果写入 `data/derived/outcome-test.json`，展示在数据说明页 |

### 更新机制档案（新英雄，或技能被调整后）

`update-data` 结束时会列出需要撰写或复核的英雄。这一步需要语言模型，在 Claude Code 里完成：

1. `npx tsx scripts/make-batches.ts --todo` 生成批次输入（`data/curated/_work/`）。
2. 让一个子任务按 `docs/curation/extract.md` 撰写档案，写到 `data/curated/heroes/`。
3. 让另一个子任务按 `docs/curation/review.md` 独立盲审，写到 `data/curated/review/`。
4. `npx tsx scripts/build-profiles.ts` 查看一致率；有分歧时按 `docs/curation/adjudicate.md` 裁定。
5. `npx tsx scripts/build-profiles.ts --stamp` 记录当前技能原文的版本，再 `npm run build:data && npm run validate`。

### 修改局内打法

打法表在 `data/curated/playbook.json`，体系的分阶段打法在 `data/curated/archetypes.json` 的 `play` 和 `against` 字段，写法规范见 `docs/curation/playbook.md`。改完运行 `npm run build:data && npm run validate && npm test`。

### 英雄教学（连招、细节、克制关系）

1. `python3 scripts/commentary/refresh-cookie.py`：从本机 Chrome 读出自己的B站登录 Cookie，写进 `.env.local`（只保存在本机，不进仓库，脚本不打印任何值）。第一次运行系统可能询问是否允许读取钥匙串。需要先在 Chrome 里登录过B站。
2. `npx tsx scripts/commentary/hero-guides.ts`：按英雄搜索教学视频并读取AI字幕到 `data/raw/commentary/`（不进仓库）。每个英雄最多取3个不同UP主的视频，“公瑾干货教学”优先；请求间隔不少于3秒，遇到风控立即停止，可以断点续跑。全部英雄约需两小时。
3. `npx tsx scripts/commentary/prepare-guides.ts` 生成提炼输入；在 Claude Code 里让子任务按 `docs/curation/guides.md` 提炼，写到 `data/raw/commentary/distilled/`。
4. `npx tsx scripts/commentary/build-guides.ts`：逐字核对每条内容的字幕出处，丢弃对不上的，把通过的条目（只有结论和视频链接）写入 `data/curated/guides/`。
5. `npx tsx scripts/commentary/build.ts && npm run build:data && npm run validate`。

教学视频里讲到的克制关系会作为“解说”证据进入关系库（权重最低一档）；如果它和官方页面的说明方向相反、又只有一个UP主这么说，就记为存疑，不参与计分；如果只是和按职业、标签推出的“机制倾向”相反，两边都保留，由净值决定。

抖音需要登录才能访问内容，没有使用。

## 我的英雄池与偏好

在“我的”页面编辑后保存在浏览器里。想长期保留或换电脑使用：在该页面导出 `profile.json`，覆盖仓库里的 `user/profile.json` 并提交，网站重新发布后以它为默认值。

## 目录

```
scripts/        抓取、整理、校验、回测与模型训练
data/raw/       第三方原始数据（职业赛逐局、公告正文、字幕），不进仓库
data/curated/   机制档案、盲审与裁定记录、规则表、战术体系定义、打法表、外号、教学提炼结果
data/derived/   脚本产出的整理结果（官方资料、聚合统计、档案合并结果、回测报告）
public/data/    前端加载的数据包
user/           个人数据的公开默认值
src/engine/     推荐引擎（纯函数）：分路推断、BP规则、关系索引、评分、阵容分析、局内打法
src/pages/      各页面
tests/          单元测试与端到端测试
docs/curation/  机制档案、解说条目、打法表的撰写、盲审、裁定规范
```

## 数据来源与限制

- 英雄资料、技能原文、官方关系：王者荣耀官网英雄详情页。
- 版本公告：官网公告接口，只保留标题、日期、链接和逐条改动。
- 职业赛BP：腾讯官方赛事数据中心。职业赛是系列赛内全局BP，与单局排位不同，所以只使用每个系列第一局的禁选次数、选手分路和同队共现，不计算胜率。原始逐局数据不进仓库。
- 路人局数据：王者营地英雄榜的公开分享页接口。它每个榜单只返回热度最高的10个英雄；完整榜单、英雄之间的对位胜率要在营地App里登录才能看到，没有使用。档位（T0/T1/T2）和各项比例都是营地的原始数字，本站不做加工。
- 排位选人顺序（蓝1 → 红2 → 蓝2 → 红2 → 蓝2 → 红1）没有找到官方文字说明，按通行顺序实现；禁用位数量可在界面上调整。
- 选人模型学的是职业队的选择；回测衡量的是“职业队实际选的英雄排在推荐列表的第几位”，不代表选得最好，也不能说明路人局的效果。结果见数据说明页。
- 局内打法的文字是人工撰写的通用战术说明，没有用对局数据验证过；同一个条目对所有满足触发条件的英雄说同样的话，不区分英雄的具体手感和当前版本强度。
- 连招与细节来自B站教学视频的自动字幕，字幕本身有识别错误；提炼由语言模型完成，脚本只能保证“视频里确实讲到了这句话”，不能保证提炼的理解完全正确，所以每条都附了可点击的出处。
